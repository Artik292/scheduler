# Несколько предметов и новый список преподавателей

Источник хранится локально: `docs/pedagogu_saraksts.xlsx`, колонки **Vārds**, **Uzvārds**, **Telpa**. Из 104 строк получены 103 преподавателя: один согласованный дубль объединён. Пробелы по краям значений убраны; кабинеты и латышские символы сохранены. Посторонние ячейки вне трёх колонок не импортируются.

## Схема

`teacher_subject` связывает преподавателей и предметы. Первичный ключ `(teacher_id, subject_id)` исключает повторение одного предмета у учителя. Преподаватель без предметов имеет ноль строк в этой таблице. `teacher.subject_id` оставлен nullable для совместимости при переключении ревизий; новый интерфейс использует таблицу связей.

Записи остаются в `vecaki` с `teacher_id`; ограничение `(teacher_id, time)` и блокировка строки преподавателя общие для всех его предметов. Часы и признак **Būs** также относятся к преподавателю целиком.

В **Skolotāji** при создании или редактировании есть поле **Priekšmeti** с выбором нескольких значений. Пустое поле допустимо. В списке родителей учитель появится после назначения хотя бы одного предмета; в административном списке он виден сразу. Удаление предмета удаляет только его связи, сохраняя учителей и их записи.

## Одноразовый импорт

`006_teacher_multiple_subjects` создаёт таблицу связей и переносит прежние назначения предметов.

`007_teacher_roster_2026` затем заменяет **всех преподавателей, их связи с предметами и все записи на приём** списком из приватного CSV. Локально файл находится в `database/imports/pedagogu_saraksts_2026.csv`; при первом облачном импорте его содержимое передаётся через Actions secret `TEACHER_ROSTER_CSV`. Таблицы `subject`, `text`, `counter`, сессии и ограничения запросов импорт не меняет. У новых преподавателей:

- `name`, `surname`, `cabinet` — значения XLSX;
- `class` и старое `subject_id` — `NULL`, связей с предметами нет;
- `available = 1`, часы 17:00–19:00, шаг 10 минут.

Замена и отметка о выполнении `007` фиксируются одной транзакцией. При ошибке весь импорт откатывается. Идентификаторы старых преподавателей не переиспользуются. Повторный запуск миграций пропускает импорт, сохраняя назначенные впоследствии предметы, расписание и новые записи родителей.

После публикации не удаляйте отметку `007_teacher_roster_2026` и не редактируйте выпущенный CSV для следующего списка: для следующей замены нужна новая миграция.

Реальные XLSX, CSV и SQL-дампы исключены из Git. Локальные файлы сохранены. Реальный CSV также исключён из сборки Docker; локальный Compose подключает папку `database/imports` только для чтения. CI использует вымышленные записи из `database/fixtures/teacher_roster.csv`.

Конвертировать исходный файл вручную или устанавливать Excel/PHP-библиотеки не нужно. Воспроизвести конвертацию и проверить результат можно Python 3 без дополнительных пакетов:

```bash
python3 bin/convert_teacher_roster.py docs/pedagogu_saraksts.xlsx database/imports/pedagogu_saraksts_2026.csv
python3 tests/teacher_roster_conversion.py
```

## Выпуск

[Релиз через pipeline](RELEASE.md) запускает обе миграции автоматически. Для этого выпуска не нужны ручной SQL-импорт и `terraform apply`.

Если `007` уже выполнена, приватный файл для следующего релиза не нужен. Если миграция ещё не применена, добавьте в GitHub **Settings → Secrets and variables → Actions → Secrets** секрет `TEACHER_ROSTER_CSV` с полным содержимым локального CSV, включая заголовок. Pipeline передаёт его только выполнению задачи миграций; файл не попадает в Git или образ. После первого импорта секрет можно удалить. Без исходного CSV начальная миграция остановится до удаления данных.
